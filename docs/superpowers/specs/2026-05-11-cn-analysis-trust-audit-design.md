# A股分析可信度审计设计

生成日期：2026-05-11

## 背景

本设计基于 `results/000002_分析报告_2026-05-11.json` 的样本审查。该报告暴露出 A 股分析链路中的系统性问题：同一股票出现价格量级冲突，基本面数据质量较低但下游仍给出激进建议，风险委员会正文建议“持有”但顶层结构化 `decision` 输出“买入”，并且 `key_points` 为空。

本轮只覆盖 A 股分析链路，不处理港股和美股。系统定位是真实交易的参考和决策支持，因此输出必须更重视数据可追溯、风险暴露、结论一致性和缺失数据透明化。

## 目标

第一阶段目标不是让报告更长，而是让报告在数据差时更诚实，在结论分歧时更一致。

成功标准：

1. 同一份 A 股报告中不允许出现互相冲突的当前价区间，例如 `16-21` 元与 `3.91-4.09` 元同时作为现价依据。
2. 顶层 `decision.action` 必须由数据质量闸门和角色专业性加权结果共同决定；解析失败时默认使用保守动作“持有”，并写入明确 reason。
3. 当当前分析角色所需核心字段缺失时，必须先输出全部缺失字段、缺失原因、是否影响当前角色分析；若影响当前角色核心结论，该角色停止后续分析，只输出缺失诊断，不生成投资方向。
4. `key_points` 不能为空，至少从风险委员会、交易员、大师共识、数据质量预警中提取 3 条证据。
5. 目标价缺失或被过滤时，不允许仍输出高置信“买入”；应改为“持有/观望”或标注目标价不可用。
6. 最终摘要和顶层推荐不能出现 agent 内部对话残留，例如“你们觉得...”。
7. 若数据缺失，必须显示具体缺失哪些数据，并说明缺失影响和后续修复入口。

## 非目标

1. 不重写所有分析师提示词。
2. 不新增港股/美股规则。
3. 不接入收费数据源。
4. 不直接自动下单或执行交易；系统输出用于真实交易前的参考、决策和人工复核。

## 推荐方案

采用 “A 股可信分析闭环”：

1. 数据审计层：统一 A 股核心事实快照和数据质量等级，明确冲突与缺失。
2. 结论一致性层：最终输出由角色专业性加权决策产生，交易员、风险委员会、大师、量化评分、基本面、技术面、新闻情绪等角色按专业性和证据质量计权；冲突时不允许静默转成买入。
3. 角色级数据准入闸门：数据质量 D、价格冲突、当前角色核心字段缺失时，该角色必须先展示全部缺失字段和缺失原因；若缺失影响当前角色分析结果，该角色不再继续生成投资方向，只输出缺失诊断。
4. 免费数据补全层：若核心缺失字段无法从现有免费数据源获取，可接入新的免费外部数据源，但必须记录来源、更新时间、字段映射和失败原因。

## 模块边界

### 1. A 股事实快照层

建议位置：新增 `tradingagents/graph/cn_fact_snapshot.py`，由 `tradingagents/graph/data_prefetch.py` 调用并写入 state。

职责：

1. 生成 `cn_fact_snapshot`，作为 A 股下游模块的统一事实入口。
2. 标准化当前价、货币、PE、PB、ROE、负债率、数据源、时间戳、缺失字段和冲突字段。
3. 保留原始工具文本作为证据，但核心事实优先引用结构化快照。

建议结构：

```json
{
  "symbol": "000002",
  "stock_name": "万科A",
  "market": "CN",
  "currency": "CNY",
  "current_price": 4.09,
  "price_source": "eastmoney",
  "price_as_of": "2026-05-11",
  "valuation": {
    "pe": null,
    "pb": 0.148,
    "roe": -0.052,
    "debt_ratio": 0.771
  },
  "quality": {
    "grade": "D",
    "score": 0.5,
    "missing_fields": [
      {
        "field": "revenue",
        "label": "营业收入",
        "required_by": ["fundamentals", "peter_lynch", "master_consensus"],
        "missing_reason": "现有免费数据源未返回利润表营业收入字段，或字段映射未命中",
        "blocks_roles": ["fundamentals"],
        "impact": "无法判断业务规模和增长趋势",
        "affects_result": true,
        "suggested_fix": "检查 A 股财务数据源的利润表字段映射；若现有免费源不可得，可评估接入新的免费外部数据源"
      }
    ],
    "conflicts": [
      {
        "code": "pe_conflict",
        "field": "pe",
        "values": [
          {"source": "akshare", "value": 44.0},
          {"source": "baostock", "value": -205.0}
        ],
        "impact": "估值判断方向可能相反"
      }
    ]
  }
}
```

缺失数据必须同时提供机器可读字段和用户可读说明：

1. `field`：内部字段名，例如 `revenue`。
2. `label`：中文显示名，例如“营业收入”。
3. `required_by`：影响哪些模块。
4. `missing_reason`：缺失原因，例如接口未返回、字段映射失败、数据源不可用、报告期缺失、权限或限流。
5. `blocks_roles`：因该字段缺失而必须停止后续分析的角色列表。
6. `impact`：缺失对分析结论的影响。
7. `affects_result`：是否影响当前分析角色的结论。
8. `suggested_fix`：后续修复入口，例如字段映射、数据源补全、接口异常；若现有免费数据源无法获取，应明确建议可接入的新免费数据源类型。

角色级准入规则：

1. 每个分析角色执行前必须声明自己的 `required_fields`。
2. 若缺失字段不影响该角色核心职责，角色可以继续分析，但必须在报告开头列出缺失字段和影响说明。
3. 若缺失字段影响该角色核心职责，角色必须停止后续投资分析，只输出缺失诊断报告。
4. 缺失诊断报告必须包含：全部缺失字段、中文名、缺失原因、影响范围、是否阻断当前角色、建议修复入口。
5. 停止分析的角色不得输出买入、持有、卖出、目标价、仓位建议或置信度。

职责：

1. 读取 `reports`、`cn_fact_snapshot`、`master_quantitative_results`、`master_data_quality`。
2. 输出结构化审计结果，不重新做投资分析。
3. 为最终决策合成层提供动作修正、置信度上限、风险提示和证据点。

### 3. 最终决策合成层

建议位置：新增 `decision_reconciler`，在 `SignalProcessor.process_signal()` 后执行，或作为 `TradingAgentsGraph` 的最终输出整理步骤。

职责：

1. 先应用数据质量闸门：价格冲突、核心字段缺失、数据质量 D 会限制动作和置信度。
2. 再按角色专业性加权计算最终动作，避免单一角色覆盖全局结论。
3. 交易员计划提供操作细节和执行路径，但不能单独决定最终动作。
4. 大师共识和量化评分提供长期投资逻辑与可复核规则。
5. 风险委员会提供风险约束和尾部风险判断。
6. 审计层可下调动作、置信度、目标价和风险分。
7. LLM JSON 抽取只作为辅助，不作为唯一事实来源。

建议初始权重如下，后续可根据回测和人工复盘调整：

| 角色 | 初始权重 | 原因 |
|------|---------:|------|
| 风险委员会 | 25% | 覆盖尾部风险、仓位安全、结论收敛，适合约束真实交易风险 |
| 交易员 | 18% | 负责把分析转为交易计划，但容易受上游叙事影响，不能单独覆盖风险结论 |
| 大师量化评分 | 18% | 规则可复核、抗幻觉能力较强，适合在数据足够时提供方向锚点 |
| 大师共识文本 | 14% | 覆盖长期投资框架和定性判断，但仍可能受提示词和数据质量影响 |
| 基本面分析师 | 10% | 对 A 股财务质量、估值和偿债能力最关键 |
| 技术面/市场分析师 | 6% | 对入场时机、支撑阻力有价值，但不能主导长期方向 |
| 研究团队经理 | 5% | 综合看涨/看跌辩论，适合提供冲突解释 |
| 新闻/社交情绪 | 4% | 反映短期催化和情绪，但噪声较高 |

动作映射：

1. 将每个角色输出映射为 `买入=+1`、`持有=0`、`卖出=-1`。
2. 每个角色得分乘以权重和证据质量系数。
3. 数据质量 D、核心字段缺失或价格冲突时，证据质量系数应降低，并限制最终置信度。
4. 加权总分 `>= 0.25` 倾向买入，`<= -0.25` 倾向卖出，介于两者之间为持有。
5. 若数据质量闸门触发 high severity，即使加权总分偏买入，也只能输出“持有/观望”或低置信小仓位建议，除非有明确、可复核的强反向证据。

对当前样本，期望输出：

```json
{
  "action": "持有",
  "confidence": 0.45,
  "risk_score": 0.7,
  "target_price": null,
  "reasoning": "A股核心数据存在价格冲突和 PE/ROE 矛盾，目标价不可用；角色加权后卖出/持有证据强于买入证据，但数据质量不足以支持高置信卖出，因此降级为持有。",
  "key_points": [
    "风险委员会明确提示尾部风险并倾向持有",
    "基本面报告提示数据质量 D 级且核心字段缺失",
    "大师共识和量化评分偏看跌"
  ]
}
```

## 审计规则

### PRICE_CONFLICT

从市场报告、基本面报告、交易员报告提取当前价、支撑位和目标价。若任一“当前价”与 `cn_fact_snapshot.current_price` 不一致，直接标注冲突；偏离幅度只用于判定 severity，而不是用于决定是否标注。当前样本中 `16-21` 元与 `3.91-4.09` 元的冲突应触发 high severity。

### DECISION_CONFLICT

从 `risk_management_decision` 或 `final_trade_decision` 抽取最终裁决。顶层 `decision.action` 必须与该裁决一致。当前样本应从“买入”修正为“持有”。

### LOW_DATA_QUALITY

若数据质量为 D，或 `missing_fields/conflicts` 包含核心字段，则限制：

1. `confidence <= 0.45`
2. 不允许高置信买入或卖出。
3. `reasoning` 必须说明数据质量问题。
4. `missing_data` 必须列出具体字段、中文名、缺失原因、影响、是否影响分析结果、是否阻断当前角色和建议修复入口。

### ROLE_DATA_GATE

每个分析角色在生成正式分析前必须通过角色级数据准入检查：

1. 定义角色必需字段，例如基本面分析至少需要营业收入、净利润、经营现金流、总资产、总负债、ROE、PE/PB；技术面分析至少需要当前价、历史 K 线、成交量；风险管理至少需要最终交易计划、波动/回撤信号、负债和现金流风险字段。
2. 检查 `cn_fact_snapshot.quality.missing_fields` 是否包含该角色必需字段。
3. 若缺失字段影响当前角色核心结论，则输出 `role_blocked=true`，并停止后续分析。
4. 若 `role_blocked=true`，该角色报告格式固定为：

```markdown
## 数据缺失诊断

当前角色：基本面分析师
结论：停止分析，原因是核心数据缺失会影响分析结果。

| 字段 | 中文名 | 缺失原因 | 是否影响结果 | 影响说明 | 建议修复 |
|------|--------|----------|--------------|----------|----------|
| revenue | 营业收入 | 利润表接口未返回或字段映射未命中 | 是 | 无法判断业务规模和增长趋势 | 检查字段映射，必要时接入新的免费财报源 |
```

5. 被阻断角色不得继续输出投资评级、目标价、仓位、置信度或交易建议。

### WEIGHTED_ROLE_DECISION

当大师、量化评分、交易员、风险委员会、基本面、技术面、新闻情绪等角色出现看涨、看跌和持有分歧时，不能由单一角色直接覆盖最终结论。必须按角色专业性、证据质量和数据完整度进行加权：

1. 专业性权重使用“最终决策合成层”的初始权重表。
2. 证据质量系数根据是否引用 `cn_fact_snapshot`、是否列出数据来源、是否存在缺失/冲突、是否给出可复核推理确定。
3. 若某角色使用了与事实快照冲突的数据，该角色权重应降低或剔除。
4. 最终输出必须给出各角色加权后的方向贡献，例如“风险委员会 25% 持有、大师量化 18% 看跌、交易员 18% 买入”。
5. 若加权结果和顶层 `decision.action` 不一致，应触发 `DECISION_CONFLICT`。

### EMPTY_DECISION_EVIDENCE

`key_points` 为空时，从风险委员会、基本面预警、大师共识中提取至少 3 条。无法提取时标记报告不可发布。

### TARGET_PRICE_INVALID

目标价缺失、被过滤或与当前价偏离过大时，最终建议不能保持高置信买入。目标价不可用要写入 `reasoning`。

### DIALOGUE_ARTIFACT

清理或标记“你们觉得”“我要问激进派”等 agent 内部辩论残留。这些内容可以保留在辩论日志中，但不能进入最终摘要和顶层推荐。

## 分阶段落地顺序

### 阶段 1：只读审计器

新增 `report_audit.py`，不改最终决策，只输出 audit result。用当前样本验证能抓到价格冲突、结论冲突、低质量数据、空 `key_points` 和对话残留。

### 阶段 2：接入最终决策合成

将审计结果和角色加权决策应用到 `decision/recommendation/key_points/confidence_score/risk_level`。先解决用户可见的最终输出矛盾，并输出各角色的权重贡献。

### 阶段 3：补 A 股事实快照

将当前价、估值、质量等级、缺失字段、冲突字段结构化。后续报告从快照取核心事实。

### 阶段 4：策略降权

数据 D 级时，看涨、看跌、交易员和风险委员会的提示词与合成规则都降权，防止激进建议从上游生成。

### 阶段 4.5：免费外部数据源补全评估

## 风险和取舍

1. 先做审计层可以快速修复用户可见矛盾，但不能立刻消除上游激进文本。
2. 事实快照会引入字段标准化工作，需要谨慎处理不同数据源命名差异。
3. 置信度上限属于规则化干预，应优先基于数据质量和结论冲突触发，避免过度保守。
4. 缺失数据清单会增加输出长度，但能显著提高后续修复效率。
5. 角色权重是初始工程假设，需要用真实报告复盘和后续回测持续校准。
6. 新免费外部数据源需要检查稳定性、许可、反爬限制和字段可信度，不能只因为免费就默认接入。
